# Trajecto ontology

`trajecto.ttl` is the core module and imports everything else. Open it in Protégé with `catalog-v001.xml` in place and
the modules and the imported ontologies in `imports/` (datAcron, SSN, SOSA) load from disk. Documentation:
`docs/` in this repository, published at `http://w3id.org/trajecto`.

`modules/profiles.ttl` is generated by `scripts/generate_profiles_module.py`. Edit the generator, not the file.

## Version 1.1.0 (2026-10-01)

Release for the public repository. The changes keep every axiom that the pipeline relies on: the POI class hierarchy,
the dwell configuration of every POI type, the purpose links, and the profile class definitions are unchanged, and
the OWL RL classification of stage 13 assigns the same profile classes. HermiT reports the DL fragment consistent
(1,190 classes). Rerunning the stage 3 and immersive-interaction queries with this ontology on the
evaluated KGs reproduces their passing (295 OSM Rome, 7,461 GeoLife) and immersive (177, 3,113) interactions exactly,
and their meaningful interactions to within 1 and 4.

### Structure

- One Turtle file per module, laid out as header, classes, object properties, data properties, annotation
  properties, individuals, then the terms borrowed from other modules.
- `poi_individuals.owl` merged into the POI module. It declared the same ontology IRI as the POI module.
- The dwell configuration links (`poi:hasTypeConfiguration`) were split between `poi_individuals.owl` and the
  temporal-dwell module. They now live in the POI module only.
- Default thresholds restored. In the KGs the thesis evaluated, `trajecto:PointOfInterest` served as its own
  configuration (meaningful from 15 s, typical 5 min, at most 60 min), linked from itself and from `poi:InfoDisplay`.
  It classifies interactions with POIs that have no category, or whose class has no configuration of its own. The
  source files had lost these durations, so a rebuild classified 21% fewer meaningful interactions on GeoLife. They
  are now the individual `poi:Default-configuration`. It replaces an unlinked `poi:PointOfInterest-configuration`
  with the same values, whose name the immersive and passing queries would have matched.
- Unused files removed: `poi_config_mappings.rdf` (a generated copy of the links) and the empty
  `hasTypeConfiguration_property.rdf`.
- `trajecto:EngagementLevel`, its three values and `trajecto:hasEngagementLevel` moved from the POI module to the core
  module, whose namespace they use.
- The core module imports all modules by their unversioned IRIs. It used to import six of them by `/1.0` IRIs.

### Metadata

Every module has the same header: `dcterms:title`, `description`, `creator`, `publisher`, `license` (the CC0 IRI,
was the literal "CC0"), `created`, `modified`, `issued`, `owl:versionInfo`, `owl:versionIRI`, `owl:priorVersion`, and
`vann:preferredNamespacePrefix`/`Uri`. The prefixes match those used in the code and the thesis (`poi`, `context`, ...).
Mixed `dc:`/`dcterms:` annotations and `dc:contributor` values that described the module were replaced.

### Terms the pipeline writes that the ontology lacked

- Core: `hasPositionIndex`; the KG analytics properties `pageRank`, `betweennessCentrality`, `communityId`,
  `hasCentralityRole` with the class `CentralityRole` and its five values; the Wikidata labels `externalLabel` and
  `externalDescription`; the similarity facets of rules SR-11 to SR-13 (`hasJaccardCategorySimilarity`,
  `hasNavigationMatch`, `hasTemporalOverlap`, `hasPurposeMatch`, `withTrajectory`, `similarityScore`,
  `TrajectorySimilarity`); the aggregates of SR-40 to SR-44.
- POI: `SignificantPOI` (stage 5), `covisitedWith` (SR-05), `followedBy` (SR-06), `hasRoom` and `hasEra` (BIRD).
- Purpose: `hasPurposeConfidenceScore` (stage 7).
- Patterns: `SteadyMovement` (BIRD).
- User: `observationCount`, `generatedSnapshot` (stage 9); `hasInferredPreference`, `forCategory`,
  `immersiveFraction`, `meaningfulFraction`, `totalVisits`, `hasAffinityFor` (SR-20, SR-21); `hasPreference` (BIRD).

### Corrections

- `trajecto:hasEasting` and `hasNorthing` were declared equivalent to `datAcron:hasLatitude` and `hasLongitude`.
  Easting is not latitude; the equivalences are removed.
- The dwell threshold properties had domain `trajecto:PointOfInterest`, but their values sit on configuration
  individuals. With the old domain, an RDFS reasoner typed the 91 configurations as POIs. The domain is now
  `poi:POITypeConfiguration`.
- `user:hasPreferences` had domain `UserProfile`, but stage 9 attaches preferences to snapshots, so every snapshot was
  inferred to be a user profile. Domain is now `ProfileSnapshot`. `learningRate` now applies to profiles and
  snapshots; `initialPreferences` to snapshots.
- `spatial:spatiallyInteractsWith` was a subproperty of `trajecto:participatesIn`, whose range (`Interaction`) clashes
  with its own (`EntityOfInterest`). It is now a subproperty of `dul:associatedWith`.
- The core module no longer restates the ranges of `datAcron:hasLatitude` and `hasLongitude`.
- The purpose concept scheme IRI `TrajectoroPurposeScheme` is now `TrajectoryPurposeScheme`, and is declared.
- `profiles:HolidayPeriodTrajectory` pointed at the undeclared `context:HolidayPeriod`; stage 4 marks holidays with
  `context:SpecialPeriod`, which it now uses.
- Orphan blank nodes and Protégé leftovers (`owl:minQualifiedCardinality` declared as an annotation property, unused
  declarations of external terms) removed.

### Deprecated

- `trajecto:NavigationStyle`, its four subclasses and `trajecto:hasNavigationStyle`: navigation styles are the
  patterns-module classes asserted with `patterns:exhibitsPattern`.
- `trajecto:hasTrajectory` and `trajecto:trajectoryRefersTo`: duplicates of `formsTrajectory` and
  `isTrajectoryFormedBy`.

### Removed

- `trajecto:hasModel`, `isActivated`, `isPaused`: undocumented properties without domain, unused by any data.
- A full copy of the W3C WGS84 vocabulary (its header, change log and terms) that the spatial module carried
  although none of its axioms use it.

### Readability

- Every term has an English label and a definition. New definitions were written for the POI classes, user-module
  terms, the core properties that had none, and the 91 dwell configurations (generated from their thresholds). The
  117 profile classes get a definition generated from their axioms.
- Label typos fixed ("Pesron", "Purspose of movement", "Mode of transporation", and others). Property labels are
  lower case, class labels title case. Top POI categories that shared a label with a subclass were relabeled
  (`poi:Leisure` "Leisure" vs `poi:LeisureFacility` "Leisure Facility", and likewise for Sports, Nightlife, Club,
  Dining, Retail).
- Every term carries `rdfs:isDefinedBy` its module, and all labels and definitions are tagged `@en`.
- Definitions describe the domain only. References to the code that builds the knowledge graph (rule numbers,
  notebooks, pipeline stages, queries, mappings) and to particular datasets were removed, so the ontology stands
  on its own.

### Known limits

- Nine properties use `xsd:duration` or `xsd:date`, outside the OWL 2 datatype map, so that part of the ontology is
  OWL 2 Full. The SPARQL stages compare dwell against these durations.
- Five SWRL rules use built-ins that HermiT does not support.
- `poi:Bench`, `poi:WaterFountain` and `poi:VendingMachine` are not placed in the POI hierarchy and not linked to their
  own dwell configurations, so their interactions use the default thresholds. Linking them changes which interactions
  count as meaningful, so it waits for a pipeline rerun.
- Two rules find a POI class's configuration in two ways: `meaningful-interaction.sparql` follows
  `poi:hasTypeConfiguration`, while `passing-interaction.sparql` and `immersive-interaction.sparql` take the
  individual named after the class (`<Class>-configuration` or `<Class>POI-configuration`). The two disagree for a few
  classes. Both are kept because together they reproduce the evaluated KGs.
